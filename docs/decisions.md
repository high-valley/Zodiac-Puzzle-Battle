## 2026-11-03 全画面へ行けるように・iPad 対応・書体・演出の強さ（仕様書 1.6.0）

- **ユーザーの依頼と決定**：
  - 空でもいいので全部の画面に遷移できるようにして、イメージを上げたい。そのあとバトル画面を検討する
  - 雰囲気は画像生成で何パターンか出したいので、そのためのプロンプトがほしい → `docs/art-prompts.md`
  - 書体はこちらのおすすめで／演出の強さは「ふつう」で様子見／iPad でも遊べるようにしたい
- **準備中の画面**：仕様書 11.3 で「未決定」だった画面（お知らせ・プレゼント・ミッション・フレンド・ギルド・ショップ・交換所・ガチャ）と期間限定イベントを、1つの部品（`src/screens/comingSoon.ts`）で作った
  - 出すもの：画面名・ひとこと・形だけの仮の中身（一覧・タブ・バナーの薄いブロック）・予定していること（仕様書の該当箇所）
  - 出さないもの：数値・値段・確率・報酬。決まっていないものをそれらしく見せると、そのまま既成事実になりやすいため。ホームの通貨・ランク・スタミナも「—」
  - ホームの配置は参考画像（01-home）に合わせた。左にお知らせ・プレゼント・ミッション・交換所、右にガチャ・ショップ・フレンド・ギルド（4つずつにして、キャラと重ならないようキャラの列を内側に寄せた）。ガチャは参考画像ではタブだが、タブは5つまで（仕様書 11.2）なので右の列のいちばん上に置き、少し光らせた
  - メニューからも全部開ける
- **書体**：見出しは **しっぽり明朝 B1**（金文字のロゴや見出しに合う、太くても品のある明朝）、本文と数値は **Zen Maru Gothic**（小さくても読みやすく、やわらかい丸ゴシック。数字の形も素直）。どちらも SIL Open Font License で、アプリに同梱して配れる。Web 版は Google Fonts から読む（日本語を文字の範囲ごとに分けて配るので、使う分だけ読み込まれる）。オフラインで遊ぶ iOS アプリ（M5）では同梱に切り替える。読めないときは端末の書体
- **iPad**：列の幅を CSS の変数（`--col`）にまとめ、iPad の縦画面で 600pt（大きい iPad は 680pt）に広げた。バトルだけは別の変数（`--col-battle`）で、画面の高さの約62%まで広げる。盤面は iPhone 358pt → iPad mini 648pt・Air 700pt・Pro 13インチ 815pt。どの大きさでも1画面に収まり、横にはみ出さないことを確かめた。iPad の背景画像の大きさを仕様書 18章に足した
- **演出の強さ**：今の強さ（「ふつう」）のまま。バトル画面を作り込むときに実機で確かめる

## 2026-11-03 編成のルールを「攻撃キャラ1人以上」に変更（仕様書 1.5.1）

- **ユーザーの決定**：攻撃3人で攻撃特化する編成も、攻撃1人＋回復2人の編成も組めるようにする。回復だけの編成はダメージを出せないので組めないようにする
- 前のルール（回復役1人以上）では攻撃3人が組めず、回復3人が組めてしまっていた
- **こちらで決めたこと**：回復役がいない編成は組めるが、編成画面に「回復役がいないので、HPは回復できません（攻撃特化）」と金色で出す（禁止ではなく知らせるだけ）
- **計測**（上手な自動プレイヤー、各200戦、全員レベル1）：
  - 攻撃3人（おひつじ・いて・ふたご／しし・さそり・てんびん／おうし・やぎ・おひつじ）：1-1〜1-3 は勝率87〜100%で、最初の編成より1〜2ターン速い。1-4・1-5 は1〜12%で、ほぼ勝てない（強攻撃を受け止められない）
  - 攻撃1人＋回復2人（しし・かに・うお／ふたご・おとめ・みずがめ）：1-5 で勝率88〜91%と最も勝ちやすいが、約15〜17ターンかかり、★2（14ターン以内）には届きにくい
  - 「攻撃特化は速いが脆い、回復を厚くすると安全だが遅い」という差として、このままにする。攻撃3人がレベルを上げてどこまで通用するかは、育成の数値を決めるときに合わせて見る

## 2026-11-02 1ターン3回まで回して「攻撃」で確定、形をL字・十字に戻す（仕様書 1.4.0）

- **ユーザーの提案と決定**：1ターンに最大3回まで回し、「攻撃」ボタンで確定する。回している間は何も消えず、必殺と消去は「攻撃」を押したときの盤面で判定する。やり直しの操作は付けない（戻したいときは逆に回して1回分を使う）。必殺の形はもとのL字・十字に戻す
- **なぜ十字が作れるようになるか**：これまで十字が作れなかったのは、3個並んだ時点で消えてしまうからだった。消えるのが「攻撃」のときだけになったので、途中で3個並べながら組み立てられる。1ターンで作れる割合（`npm run bench`、実戦に近い盤面 200 面、1回 → 2回以内 → 3回以内）は L字 3% → 28% → 56%、十字 0% → 11% → 31%、ピンク2×2 16% → 45% → 76%
- **こちらで決めたこと**：
  - 「攻撃」は1回以上回したときだけ押せる（0回で攻撃はできない）
  - 行動するキャラは「攻撃」を押すまで替えられる
  - 回している間、「攻撃」で消える3個並びに白い輪、選んでいるキャラの必殺の形に金の輪をつける（消えずに残っているので、何が起きるか見えるようにするため）
  - 回した途中の分と選んだキャラも保存する（再読み込みで回した分を取り消せないように、選んだキャラもそのまま戻るように）
  - 敵の数値を変えたので、このルールに変える前に保存された途中バトルは、はじめからになる（保存した状態が今のデータと合わないため）
  - 「攻撃」ボタンは盤面のすぐ下、残り回数の表示の横に置く（参考画像の「攻撃開始」ボタンにあたる）
- **数値の調整**：1ターンのダメージが約80から約160に増えたので、敵のHPと攻撃を作り直した。1ターンが長くなった（3回まで回して攻撃）ので、1戦のターン数の目安は 1-1 約5ターン 〜 1-5 約14ターンに下げた（1戦2〜4分の目安に合わせる）。★2の目標ターンも合わせて下げた
  - 上手な自動プレイヤー（skilled）：1-1 勝率100%・約5ターン、1-4 約92%・約12ターン、1-5 約76%・約14ターン。でたらめに回すと 1-1 は約1割、1-2 以降はまず勝てない
  - ★2の目標ターンは上手な人の平均くらいにしたので、★2に届くのは半分ほど（やり込みの目標）
  - 自動プレイヤーは3回までの回し方に合わせて作り直した。skilled は1回ずつ良い回し方を選び、必殺の形があと1〜2個ならそこへ近づける（上手な人の目安）。expert は3回までを全部調べる（上限の目安）
- 角・×字の記録（下の節）は経緯として残す

## 2026-11-02 M3（ステージ・保存・画面）で決めたこと

ユーザーから「判断して進められるところまで進めて」と任されたので、次はこちらで決めた。変えたい点があれば直す。

- **第1章は5ステージ、1ステージ1戦**。敵は 星屑のかけら・夜霧の獣・欠けた月の番人・流れ星の狩人・星喰いの影（`src/data/enemies.ts`・`stages.ts`）
- **敵の強攻撃を足した**（仕様に無い敵の行動）：決まったターンごとに、ふつうの攻撃の代わりに強い攻撃をする。敵の欄に「強攻撃まで あと○ターン」と出し、直前のターンは赤く出す。回復役の出番をつくり、先を読んで動く判断を増やすため。1-3 から登場
- **★の条件**：★1＝勝つ、★2＝目標ターン以内に勝つ、★3＝さらにパーティーHPを50%以上残す。目標ターンは、自動プレイヤー（skilled）の平均ターン数に合わせた（上手に遊んでも★2が取れるのは半分くらいになる。★2・★3はやり込みの目標にするため、意図どおり）
- **数値の調整の目安**：1手先だけ見る自動プレイヤー（skilled）で、1-1 は勝率100%・約6ターン、1-5 は勝率約80%・約18ターン。でたらめに回すと 1-1 でも勝率は約3割、1-3 以降はほぼ勝てない。自動プレイヤーは見えている盤面だけで判断し、補充で落ちてくるオーブ（seed の先）は見ない
- **実際の人の勝率や時間は計測していない**。サーバーが無いので集められない。計測は `npm run bench` の自動プレイヤーで代える
- **進行の保存**：クリアした★といちばん少ないターン数、途中のバトル（1ターンごと）を端末に保存する。再読み込みや iPhone でタブが閉じられても、つづきから遊べる。リタイアしたバトルは記録しない。報酬や通貨は置かない（CLAUDE.md・仕様書 19章）
- **次のステージは、前のステージを★1以上でクリアすると開く**
- **勝敗が決まったターンは、演出より先に記録する**。演出の途中で再読み込みや「戻る」をしても、勝ちが消えたり負けた手をやり直せたりしないようにするため
- **途中のバトルを続けられるのは、保存した状態が今のデータと合うときだけ**（最大HP・強攻撃の間隔・開いているステージ）。数値を調整したあとは、古い途中バトルははじめからになる
- **ホームは M3 の簡易版**（ロゴ・3人の星座・冒険・つづきから・遊び方・設定）。下のタブバーは、編成・育成ができる M4 で付ける
- **リザルトの「編成へ」は、M4 までは「クエスト選択へ」**
- **設定に「演出の速さ（ふつう／はやい）」と「回転ボタンを出す／出さない」を足した**。演出の速さはバトルの上の帯の「×1／×2」でも切り替えられる
- **遊び方はタブ（基本操作／必殺技／バトルの基本）にし、「強攻撃と★」のカードを足した**
- **iPhone SE のような背の低い画面では、敵の欄を縮めて操作説明の一行を隠し、盤面の大きさを保つ**（仕様書 11.9）

## 2026-11-01 M2（必殺演出・操作チュートリアル・効果音）で決めたこと

- **効果音は Web Audio で合成する**（音声ファイルを使わない）。オフラインで動き、素材の権利の心配がない。素材に差し替えるときは `src/audio/sound.ts` の鳴らし方だけ替える。出来事と音の対応は `src/audio/cues.ts`（純粋な関数）
- **効果音は最初からオン**。上の帯のボタンでオン/オフでき、端末に記憶する。iOS 17 以降は消音スイッチに従う種類（ambient）で鳴らす
- **遊び方は初回だけ自動で開く4枚の説明カード**（回す・3個そろえる・必殺・HP）。「?」ボタンでいつでも開ける。見たかどうかは端末に記憶する。仕様 11.2 の「段階的に開放する」チュートリアルは、キャラやオーブが増える段階で改めて作る
- **設定は localStorage に保存する**。保存できない環境では既定値で動く
- 遊び方は「とばす」や Escape で閉じても「見た」扱いにする（次からは自動で開かない）
- ターンの演出中は「?」（遊び方）も押せない。効果音のオン/オフは演出中も切り替えられる
- 音が出せない環境（AudioContext を作れない等）では、音なしでそのまま遊べる
- **必殺演出**：形のオーブを金の星座線で結んで光らせ、キャラ名と技名を盤面の上に出す。そのターンのダメージ・回復の数値と音を大きくする

## 2026-11-01 必殺に使ったオーブを消す（仕様 9.3・16 章 2 の変更）

- **理由**：仕様 9.3 のままだと、形が盤面に残り続けて毎ターン必殺が出る。特にピンク2×2は縦横3個に並ばないので消えず、おとめ座で離れた交点を回すだけで毎ターン＋110回復となり、負けなくなっていた
- **決めたこと**：必殺が出たら、その形のオーブを最初の消去で通常マッチと一緒に消す（重なったマスは1回だけ消す）
- 必殺だけで消えたオーブは通常効果（攻撃・回復）を出さない。縦横3個並びの通常マッチにもなっている分は、これまでどおり通常効果も出る
- 必殺だけの消去は連鎖の段数に数えない。そのあと落ちてきたオーブでできた通常マッチは1連鎖目から数える
- 仕様 9.3 の「必殺条件に使ったオーブは同じターンの通常消去判定と重複して構わない」はそのまま（重なっても両方の判定に使う）

## 2026-11-01 M1（最小プレイアブル）で決めたこと

- **画面は React を使わず、TypeScript ＋ DOM で書く**。M1 はバトル画面1枚だけなので。メニュー・編成・育成の画面が増える M3 以降で React の採用を改めて判断する
- **初期盤面は通常マッチが無いように作る**（仕様 7.3 の「要調整」）。色を1マスずつ決め、左に2個・上に2個同色が続く色を候補から外す。偶発的な初期マッチで1ターン目に勝手に消えるのを避けるため。必殺の形は初期盤面にあってもよい（仕様 9.3）
- **連鎖が8段に達したら、残ったマッチはそのまま次のターンに持ち越す**（次の回転のあとに消える）
- **補充の乱数の引き方**：左の列から、各列は下の空きから順に引く。再現性テストはこの順番に依存する
- **敵の行動は毎ターン一定量の攻撃**（`ENEMY.attack`）。敵HP・攻撃量・各キャラの係数・必殺の威力はすべて仮値で、`src/data/` で差し替える
- **おひつじ座の青「防御低下」はダメージだけ**。デバフの仕組みは後のフェーズで入れる
- **交点の判定**：押した位置にいちばん近い交点を選ぶ（盤面の端を押しても端の交点になる）。タップだけ（移動が閾値未満）は選択のみで、回転ボタンがその交点に効く
- **選んでいる交点は画面側で持つ**（仕様 13 章の `BattleState.selectedIntersection` はエンジンの状態に入れない）。選択はターンの結果に影響しないため
- **回復の出来事（`heal`）の量は、実際に増えた量**。最大HPで頭打ちになった分は含めず、満タンなら出来事自体を出さない
- **ターンの演出中は「やり直す」も押せない**（途中で新しい戦闘を作ると、古いターンの結果で上書きされるため）
- **package-lock.json はまだ無い**。作成した環境から npm レジストリに届かなかったため、CI は `npm install` で入れている。手元で `npm install` したら lock を足し、CI を `npm ci` に替える
