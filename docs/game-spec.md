# 星座パズルバトル — ゲーム仕様書

- 文書バージョン：1.0.0
- 作成日：2026-11-01
- ステータス：コア仕様確定／バランス数値は仮
- 開発形式：GitHubリポジトリ → GitHub Pages Webアプリ → iOSアプリ（App Store）
- 仮称：星座パズルバトル（正式タイトル未定）

## 1. コンセプト

片手で操作できる2×2回転パズルと、12星座のキャラクター育成を組み合わせた、短時間で遊べる戦略型パズルRPG。3人編成からターンごとに1人を選び、盤面に応じた攻撃・回復・固有必殺技を使う。難しい形の完成による高威力と、プレイヤーの盤面把握・操作技術による上達感を重視する。

### 1.1 設計原則
1. 操作は直感的、上達の幅は大きくする。
2. キャラクターごとの固有必殺技は「特定色×特定の配置形状」で発動する。
3. **通常消去の形ボーナスは設けない**。L字や十字などの形は固有必殺技の条件としてのみ使う。
4. どの攻撃キャラでも赤・青・緑から攻撃でき、特定色不足による行動不能を避ける。
5. 育成したお気に入りのキャラを長く使えるよう、特定キャラ必須のギミックは避ける。
6. ゲームの判定・乱数・戦闘計算を描画UIから分離する。

## 2. プラットフォームと開発工程

| フェーズ | 対象 | ゴール |
|---|---|---|
| P0 | ローカル／GitHub | 型定義、ゲームエンジン、テスト、最小UI |
| P1 | GitHub Pages | iPhoneのSafariから2×2交点操作を試せる |
| P2 | Web版ベータ | バトル、育成、ステージ、セーブ、演出、音、アクセシビリティ |
| P3 | iOS | CapacitorでiOSプロジェクト生成、実機検証、TestFlight |
| P4 | App Store | 審査・公開・アップデート運用 |

### 2.1 推奨技術
- TypeScript + Vite：ビルドと開発基盤。
- React：メニュー・編成・育成などの一般UI（採用推奨、必須ではない）。
- バトル盤面：初期はCSS/DOM/Pointer Eventsで実装し、必要に応じてCanvas/PixiJSへ移行。
- Vitest：盤面回転、マッチ、必殺判定、ダメージ、再現性テスト。
- GitHub Actions + GitHub Pages：mainブランチへの反映後にビルド・公開。
- Capacitor：完成したWebアプリのiOSネイティブコンテナ化。
- バックエンド：MVPでは不要。オフラインのローカル保存を優先。オンライン機能は後から検討。

### 2.2 iOS化への注意
- Pages公開できることとApp Storeに提出できることは別。後者にはApple Developer Program、アプリ署名、iOSビルド、審査対応が必要。
- 通常のiOSビルドはmacOSとXcodeが前提。Macがない場合は信頼できるクラウドビルド環境を検討。
- Webアプリを単にURL表示するだけのアプリではなく、オフライン動作、ネイティブらしい操作体験、適切な機能を備える。

## 3. ゲームモード・進行

### 3.1 MVP対象
- シングルプレイヤー、PvE、1ステージ単位のバトル。
- 3人編成：攻撃役2人＋ヒーラー1人。
- 1回の戦闘は目標2～4分。実測して調整する。
- 盤面5×5、オーブ4色。
- 各ターンで操作キャラ1人を選択し、2×2回転を1回実行する（MVP暫定）。
- 勝利：敵HPが0。敗北：パーティー共通HPが0。

### 3.2 将来対象
- ストーリーと12星座キャラの段階的加入。
- レベルアップ、覚醒、装備、76星座由来の追加スキル。
- 複数敵、ボスギミック、クエスト、セーブ同期（必要時のみ）。

## 4. パーティー・HP

### 4.1 パーティー
- 同時編成可能人数：3。
- MVPではおひつじ座（攻撃）、いて座（攻撃）、おとめ座（回復）固定。
- 戦闘中、プレイヤーは毎ターン3人のうち1人を選択する。
- 未選択キャラはそのターン行動しない。

### 4.2 HP（合計1本）
- 各キャラに「最大HPへの寄与値」は持たせる。
- **パーティー最大HP = 3人の最大HP寄与値の合計**。
- 現在HPはパーティー共通の1値だけを持つ。個別HP、個別戦闘不能はMVPでは設けない。
- 敵の攻撃は共通HPを減らし、ヒーラーの回復は共通HPを回復する。
- 現在HPは0～最大HPに収める。編成変更による最大HP変更時の現在HP調整方式は育成実装時に確定する。

## 5. 盤面仕様

### 5.1 サイズと色
- 5行×5列、計25マス。
- 赤（R）・青（B）・緑（G）・ピンク（P）の4色。
- **オーブ自体の形状は全色共通**。色ごとのアイコン・コントラスト・形状補助で色覚多様性に対応する。
- 後の「形」は、複数オーブが盤面上に作る配置であり、オーブそのものの変形ではない。

### 5.2 回転単位
- 隣接2行×2列（4個）を1組として90°回転する。
- 回転可能な交点は4行×4列、計16か所。
- 右（時計回り）または左（反時計回り）の2方向。
- 回転では4個の値を入れ替え、その他の21マスは動かさない。

### 5.3 回転の数学的定義
2×2を `[A B; C D]` とした場合：
- 時計回り：`[C A; D B]`
- 反時計回り：`[B D; A C]`

## 6. 入力操作：C案「交点スワイプ」

### 6.1 標準入力
1. 盤面の4オーブの中心交点を押す。
2. 対象2×2の輪郭をハイライト表示する。
3. 指を右へ一定距離スワイプ → 時計回り、左へスワイプ → 反時計回り。
4. 指を離す時点で方向確定し、回転を実行する。
5. 移動量が判定閾値未満の場合は「選択のみ」で回転しない。

### 6.2 操作代替
- 交点タップで選択後、「左回転」「右回転」ボタンでも操作できる。
- 盤面周囲のスクロール誤発動を防ぐため、盤面のジェスチャー領域に `touch-action: none` を適用する。
- 盤面選択のタップ判定は見かけより大きくする。隣接交点と判定が重なった場合は最も近い交点を選ぶ。
- スワイプ方向は水平方向を優先し、縦移動が大きいジェスチャーはキャンセルする。
- 指を離す前にキャンセルした場合は盤面を変更しない。

### 6.3 MVPでの閾値（暫定）
- 水平スワイプ距離：22 CSS px以上。
- `abs(dx) > 1.2 * abs(dy)` を満たすこと。
- タッチ/マウスの両方をPointer Eventsで実装。
- 実機で誤操作率を計測し、閾値と操作領域を調整する。
- 回転中は再入力をロックし二重発火を防ぐ。

## 7. 基本消去・連鎖

### 7.1 通常マッチ
- **同色3個以上が縦または横に連続すると消去対象**。
- 同時に成立した縦横ラインは、交差箇所を重複計上しない。
- 対角線上の3個は通常マッチ対象外。
- 3個以上を消すと、選択キャラに応じた通常効果が発動する。
- 直線の長さやL字・十字・四角そのものによる追加倍率は **なし**。
- 一度に消したオーブ数や連鎖段数による基礎ダメージ増加は可（形ボーナスではない）。

### 7.2 落下と補充
1. 成立した全マッチを同時確定。
2. 消去対象を一括削除。
3. 各列で下側に既存オーブを詰める。
4. 空きに上から新しいオーブを補充する。
5. 3個以上のマッチが成立したら連鎖を繰り返す。
6. 連鎖上限はMVPで8段（無限ループ回避の暫定値）。

### 7.3 乱数
- 乱数生成器のseedをゲーム状態に含める。
- 同じ初期盤面、seed、操作列なら同じ結果になること。
- ステージ開始時に偶発的な初期マッチを許すか、リロールで除去するかは要調整。

## 8. 色別アクション／3人の仮性能

### 8.1 共通方針
- おひつじ座・いて座は赤・青・緑の消去で攻撃する。
- おとめ座はピンク消去で回復する。
- 攻撃キャラ選択中のピンク消去、ヒーラー選択中の赤・青・緑消去は、MVPでは直接ダメージ・回復を発生させない（連鎖には寄与する）。
- 各色の効果はキャラ固有。色と属性を固定で結び付けるかは正式決定しない。

| キャラ | 赤 | 青 | 緑 | ピンク |
|---|---|---|---|---|
| おひつじ座 | 高威力攻撃 | 防御低下を伴う攻撃 | 連続斬撃 | 直接効果なし |
| いて座 | 拡散射撃 | 貫通射撃 | 連射 | 直接効果なし |
| おとめ座 | 直接効果なし | 直接効果なし | 直接効果なし | 共通HP回復 |

※単体敵しかいないMVPでは拡散・連射の効果差が分かりにくい。表示上の技名だけでなく、連射＝複数回ヒット、拡散＝複数ターゲット適用など、複数敵実装時の挙動を別定義する。

### 8.2 ダメージ・回復（仮計算）
- `通常量 = Σ(色ごとの基礎係数 × 消去個数 × 連鎖倍率)`
- 仮の連鎖倍率：`1 + 0.25 × (連鎖段数 - 1)`。
- プレイヤーのレベル、攻撃力、敵防御、特性倍率はゲームエンジンの別レイヤーで計算。
- 形の一致による通常攻撃倍率アップはない。
- 数値はゲームバランス検証前の仮値。表示・定義とも設定データで差し替え可能にする。

## 9. キャラ固有の「形」による必殺技

### 9.1 設計意図
通常技と異なり、**特定の色のオーブが、指定した形に並んだ場合に固有必殺技を発動**する。形は位置依存でなく盤面中の任意位置に配置可能。これは「形ボーナス」ではなく必殺技の発動条件である。

### 9.2 MVPの発動条件
| キャラ | 対象色 | 形 | 必殺技 |
|---|---|---|---|
| おひつじ座 | 赤 | L字5個（縦3＋横3、端点1個共有） | 炎角・紅蓮衝（大ダメージ） |
| いて座 | 青 | 十字5個（中央＋上下左右1個） | 天穿つ星矢（大ダメージ） |
| おとめ座 | ピンク | 2×2正方形4個 | 聖女の祝福（共通HP大回復） |

### 9.3 判定の約束
- 必殺判定タイミングは **2×2回転直後、通常マッチを消す前**。
- 発動は**そのターンに選んだキャラのみ**。
- L字は上下左右の90度回転4方向に対応。十字は1種類。正方形は1種類。
- 必殺条件に使ったオーブは、同じターンの通常消去判定と重複して構わない（MVPルール）。
- 必殺は盤面中に条件が存在する場合に自動発動する。
- 1ターンにつき固有必殺技は最大1回とする。
- 特定形が初期状態から成立している場合でも、回転直後に残っていれば発動する（MVP）。
- **【2026-11-01 変更】必殺が出たら、その形のオーブを最初の消去で通常マッチと一緒に消す**。必殺だけで消えたオーブは通常効果を出さず、連鎖の段数にも数えない（詳細と理由は `docs/decisions.md`）。
- **将来の改善候補**：回転で新たに形を作ったときだけ発動する／条件成立後の任意タイミングで手動発動する／発動にゲージ消費を要求する。MVPでは採用しない。

### 9.4 複数条件と優先順位
- 必殺と通常マッチが同時成立した場合は、必殺判定→通常消去→連鎖→総合ダメージ処理の順。
- 必殺に必要な形だけ成立し、縦横3個消しが不成立でも、必殺技は発動する（特にヒーラーの2×2）。
- 盤面内の他の形は追加倍率に使わない。

## 10. ターン・戦闘処理順

`プレイヤーがキャラ選択 → 交点選択 → スワイプ確定 → 2×2回転 → 固有形判定 → 通常マッチ／連鎖 → 攻撃・回復反映 → 敵行動 → ターン更新 → 次ターン入力待ち`

- 1回転を1ターンとして扱う（MVP）。
- 同ターンの回転回数を増やす、制限時間内に連続回転する方式は後日比較試験。
- 敵HPが0になったら敵行動なし。
- 味方HPが0になったら敗北。0未満にはしない。
- 同ターンに回復と敵ダメージが発生する場合は、味方回復→敵の攻撃の順。
- ターン処理が終わるまで操作受付を一時停止する。

## 11. UI／UX

### 11.1 縦画面（スマホ最優先）
1. ステージ番号・ターン・メニュー。
2. 敵の立ち絵、敵HPバー。
3. 5×5オーブ盤面、16交点、選択2×2ハイライト。
4. 選択中キャラの固有必殺技の形（3×3程度の縮小プレビュー）。
5. キャラ選択カード3枚。
6. **共通HPバー1本だけ**（個別HPバーは表示しない）。
7. ダメージ、回復、連鎖数、必殺演出。
8. 代替操作として左回転・右回転ボタン（設定で非表示可能にする余地あり）。

### 11.2 基本ユーザー体験
- 通常マッチ時は短い消去アニメとキャラごとの攻撃演出。
- 固有形成立時は固有必殺演出と大きなダメージ／回復数値。
- スワイプの方向を視認可能にし、操作前のハイライト・仮プレビューを今後検討。
- タッチ面積・端末セーフエリア・可読性・色覚多様性・軽量なエフェクトを考慮。
- オーブ／スキルの説明はチュートリアルで段階的に開放する。

## 12. 育成／スキル（後続フェーズ）

### 12.1 12星座
- 基本キャラ12体を主人公側の主力とする。
- 育成はレベルアップ、覚醒、固有性能の強化などを用意。
- お気に入りの2アタッカー＋ヒーラーでほぼ全クエストを攻略できるバランスを目標にする。

### 12.2 76星座
- 残り76星座は装備スキル・パッシブ・追加行動のモチーフとして扱う（詳細未決）。
- 盤面操作を自動化しすぎず、プレイヤーの腕前が反映される効果を優先。
- 実在の88星座すべてに古代神話が存在するわけではないため、物語設定は天文学的由来や伝承を区別して調査する。

## 13. ゲーム状態の型（案）

```ts
type OrbColor = 'red' | 'blue' | 'green' | 'pink';
type HeroId = 'aries' | 'sagittarius' | 'virgo';
type Direction = 'clockwise' | 'counterclockwise';
type Board = OrbColor[][]; // 5x5

interface BattleState {
  board: Board;
  selectedHero: HeroId;
  selectedIntersection: { row: number; col: number } | null; // row, col: 0..3
  turn: number;
  partyHp: number;
  partyMaxHp: number;
  enemyHp: number;
  enemyMaxHp: number;
  rngSeed: number;
  status: 'playing' | 'victory' | 'defeat';
}
```

エンジン関数案：
- `rotate2x2(board, row, col, direction): Board`
- `findMatches(board): MatchGroup[]`
- `detectHeroSpecial(board, heroId): SpecialResult | null`
- `collapseAndRefill(board, rng): {board, rng}`
- `resolveTurn(state, action): TurnResult`
- `formatTurnEvents(result): BattleEvent[]`

## 15. 受け入れ条件（MVP）

### 操作
- [ ] 16か所の交点それぞれを選択できる。
- [ ] 左スワイプで反時計回り、右スワイプで時計回りになる。
- [ ] 閾値未満の移動は回転しない。
- [ ] 交点タップ＋回転ボタンも使える。
- [ ] タッチ後、ページスクロールや別交点の誤選択を極力起こさない。

### パズル
- [ ] 2×2回転で4個以外の位置は不変。
- [ ] 3個以上の縦横ラインのみ通常消去。
- [ ] 消去→落下→補充→再判定の連鎖が正しく処理される。
- [ ] 同seed＋同操作列で同じ結果。
- [ ] **形ボーナス倍率は存在しない**。

### キャラ・必殺
- [ ] 3人から行動キャラを選択可能。
- [ ] おひつじ座の赤L字が回転4方向で判定される。
- [ ] いて座の青十字が判定される。
- [ ] おとめ座のピンク2×2が判定される。
- [ ] 必殺条件を満たしても、未選択キャラの技は発動しない。
- [ ] 2×2のピンクが消去不能でも、おとめ座の必殺回復は成立する。
- [ ] 共有HPが1本だけ表示され、回復と被弾が正しく反映される。

### Web→iOS
- [ ] GitHubのmain反映でPagesに自動デプロイ。
- [ ] iPhone AirのSafari実機で視認性・操作・リロードを確認。
- [ ] PWA/ネイティブ化に向け、ゲームロジックがブラウザ固有APIに依存しない。

## 16. 未決定事項・優先検証

1. **1ターン1回転**が面白いか、時間制限内の複数回転が面白いか。
2. 2×2回転直後の必殺判定が「以前からその形があっただけ」でも発動する問題をどう扱うか。
3. 5×5盤面で赤L字5個／青十字5個がどの頻度で完成するか。必殺が希少すぎないか。
4. ピンク2×2必殺の難度が攻撃必殺より易しすぎないか。
5. 結果の演出が即時で終わるか、連鎖中の入力を一時停止するか。
6. 76星座スキルの設計、攻撃キャラ間の性能差、編成自由度。
7. 敵が複数体の場合のターゲット選択、範囲、貫通の意味。
8. オフライン進捗保存、バックアップ、クラウド同期の必要性。
9. 縦画面で交点の誤操作率が許容できるか。

## 17. 開発順序（優先度）

**M1：最小プレイアブル**
- 盤面表示、16交点スワイプ、左右回転、3個消し、連鎖、3キャラ、共通HP、敵1体、勝敗。

**M2：固有形**
- L字・十字・正方形の自動判定、必殺演出、操作チュートリアル、効果音。

**M3：バランス・UX**
- 発動率・勝敗率計測、キャラ差分、タッチ操作の改善、状態保存、ステージ構成。

**M4：コンテンツ**
- キャラ育成、シナリオ、各星座の技、新敵、装備スキル。

**M5：iOSリリース準備**
- Capacitor対応、iOSビルド、TestFlight、性能・アセット・プライバシー確認、App Store申請。
