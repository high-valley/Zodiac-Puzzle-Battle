## 1. コンセプト

片手で操作できる2×2回転パズルと、12星座のキャラクター育成を組み合わせた、短時間で遊べる戦略型パズルRPG。1〜4人の編成の全員が同時に行動し、それぞれ自分の色のオーブで攻撃・回復・固有必殺技を使う。難しい形の完成による高威力と、プレイヤーの盤面把握・操作技術による上達感を重視する。

### 1.1 設計原則
1. 操作は直感的、上達の幅は大きくする。
2. キャラクターごとの固有必殺技は「特定色×特定の配置形状」で発動する。
3. **通常消去の形ボーナスは設けない**。L字や十字などの形は固有必殺技の条件としてのみ使う。
4. どの攻撃キャラでも赤・青・緑から攻撃でき、特定色不足による行動不能を避ける。
5. 育成したお気に入りのキャラを長く使えるよう、特定キャラ必須のギミックは避ける。
6. ゲームの判定・乱数・戦闘計算を描画UIから分離する。

## 4. パーティー・HP

### 4.1 パーティー
- 同時編成可能人数：**1〜4人**（2026-11-03 変更。それまでは3人）。仲間が3人のうちは3人まで。最初の新しい仲間（緑のてんびん座。12.6）が加わると、4人目の枠が使えるようになる。
- MVPではおひつじ座（攻撃）、いて座（攻撃）、おとめ座（回復）固定。**M4 からは12星座から自由に選ぶ**（編成のルールは 12.5）。
- **2026-11-03 改定**：行動するキャラは選ばない。出撃した仲間全員が同時に行動し、各キャラは自分の色のオーブが消えたときだけ動く（12.7）。

### 4.2 HP（合計1本）
- 各キャラに「最大HPへの寄与値」は持たせる。
- **パーティー最大HP = 出撃した仲間の最大HP寄与値の合計**。寄与値はレベルで増える（12.4）。
- 現在HPはパーティー共通の1値だけを持つ。個別HP、個別戦闘不能はMVPでは設けない。
- 敵の攻撃は共通HPを減らし、ヒーラーの回復は共通HPを回復する。
- 現在HPは0～最大HPに収める。
- **【M4】編成はバトルの外でだけ変えられる**。途中のバトルは始めたときの編成・レベルのまま保存して続けるので、バトル中に最大HPが変わることはない。バトルの後に上がったレベルは次のバトルから効く。

## 5. 盤面仕様

### 5.1 サイズと色
- 5行×5列、計25マス。
- 赤（R）・青（B）・緑（G）・ピンク（P）の4色。
- **オーブ自体の形状は全色共通**。色ごとのアイコン・コントラスト・形状補助で色覚多様性に対応する。
- 後の「形」は、複数オーブが盤面上に作る配置であり、オーブそのものの変形ではない。

### 5.2 回転単位
- 隣接2行×2列（4個）を1組として90°回転する。
- 回転可能な交点は4行×4列、計16か所。
- 右（時計回り）または左（反時計回り）の2方向。
- 回転では4個の値を入れ替え、その他の21マスは動かさない。

### 5.3 回転の数学的定義
2×2を `[A B; C D]` とした場合：
- 時計回り：`[C A; D B]`
- 反時計回り：`[B D; A C]`

## 6. 入力操作：C案「交点スワイプ」（2026-11-04 から、指で円を描いて回す）

### 6.1 標準入力
1. 盤面の4オーブの中心交点を押す。
2. 対象2×2の輪郭をハイライト表示する。
3. **選んだ 2×2 を、つまみを回すように指で回す（2026-11-04 改。ユーザーの要望「選んだ範囲のオーブを、そのまま回すイメージで」）**：4個のどれかを押したまま、2×2 の中心のまわりに円を描くと、4個が指の角度にぴったり付いて回る。時計回りに描けば時計回り、逆なら反時計回り。途中で逆へ戻せば、そのまま戻る。何周でも続けて回せて、90度ごとに1回と数える（1ターンに残っている回数で止まる）。
4. 指を離したとき、最後の90度のうち半分（45度）より多く回していれば回しきり、45度以下なら手前の位置へ戻る。速く払ったときは、少し（90度の15%以上、22px以上動かして）回していれば回しきる。回してもその場では何も消えない（10章）。
5. 動きが小さい（4px 未満）ときは「選択のみ」で回転しない。中心のすぐ近く（0.35マス以内）では指の角度を読まない（わずかな動きで角度が大きくぶれるため）。
6. 1ターンに3回まで回せる。回し終えたら（1回以上）「攻撃」ボタンでターンを確定する。**3回回しきったら、「攻撃」を押さなくても自動で攻撃する**（2026-11-04 ユーザーの要望。最後の盤面を見せるため 0.35秒待つ。`src/data/balance.ts` の `AUTO_ATTACK_DELAY_MS`。3回回したところでアプリを閉じた途中のバトルは、開き直すとそのまま攻撃する）。3回回したあとは、それ以上回せない（やり直しの操作は無く、戻したいときは逆に回して1回分を使う）。

### 6.2 操作代替
- ~~交点タップで選択後、「左回転」「右回転」ボタンでも操作できる。~~ → **2026-11-04 ユーザーの決定で回転ボタンはなくした**（指で回す操作だけで足りるため。空いた所に仲間の必殺の形を並べる）。
- 盤面周囲のスクロール誤発動を防ぐため、盤面のジェスチャー領域に `touch-action: none` を適用する。
- 盤面選択のタップ判定は見かけより大きくする。隣接交点と判定が重なった場合は最も近い交点を選ぶ。**ただし今選んでいる 2×2 の4個の上を押したときは、選んだまま**にする（2026-11-03。4個のどれかを押してスワイプするので、隣を選んでしまわないように）。ほかの交点の星の近く（0.3マス以内）を押せば、その交点に移る。
- **オーブを押して運ぶ（2026-11-12 ユーザーの要望）**：オーブのまんなか寄りを押したときは、まわりの交点がほぼ同じ距離で、少しのずれで意図と違う 2×2 が選ばれていた。そこで、選んでいる 2×2 の上でも交点の星の近く（0.3マス以内）でもない所を押したときは、いったん近い交点を選んで見せ、**指が 0.3 マス動いたところで、動かした向きから 2×2 を決め直す**（`pickByDrag`）。候補は、押したオーブの四隅の交点（盤面の中のものだけ）。
  - **まっすぐ運んだとき**（横ぶれ＝進む向きに直角な動き ÷ 進む向きの動き が 0.25 未満）：進む向きの側の交点。右へ運べば、押したオーブと右隣のオーブをふくむ 2×2 になる。残りの2つ（上か下か）は、押した所に近い方。
  - **少し弧を描いたとき**（横ぶれ 0.25〜0.6）：進む向きの側で、弧の内側（横ぶれと反対の側）。円を描けば、その円の中心の 2×2 になる。
  - **ななめに動かしたとき**（横ぶれ 0.6 以上）：その動きが「まわりを回る動き」になる2つの交点のうち、押した所に近い方。
  - 同じ近さなら、押した瞬間に選ぶ交点と同じ側（下・右）。
  - 決めるまでに動かした分も、回した量に数える。ただし決まった瞬間に付けるのは 90度の 35% まで（盤面が飛ばないように）。動かさずに離せば、近い交点を選んだだけになる。回せなくなったとき（別の指で攻撃を押したなど）は、決めるのを待っていた分も捨てる。
  - 値は `SWIPE.decideCells`・`straightRatio`・`diagonalRatio`・`decideMaxTurns`。
- 選んだ 2×2 は、太めの金の枠・うすい金の地・四隅の星で示し、まんなかの交点の星を大きくする（ほかの交点の星は控えめに）。押している間は枠を強く光らせ、別の交点に移ったときは枠が一度光る。回す向きの矢印は出さない（2026-11-04。4個そのものが指に付いて回るので）。
- 指を離す前にキャンセルした場合は盤面を変更しない。

- **回し方を設定で選べる（2026-11-12 ユーザーの決定）**：設定の「オーブの回し方」で、いつでも切り替えられる。初期値は「押して回す」。
  - **押して回す**：上のとおり（押した所の 2×2 を選び、そのまま指で回す）。
  - **タップで選ぶ**：オーブを軽くタップする（`SWIPE.tapSlop` より動かさない）と、押した角の側の 2×2 を選ぶ（回さない）。選んだ 2×2 の外を暗くし、枠を太くする（攻撃の演出中・補充中は暗くしない）。選んだあとは盤のどこをなぞっても、選んだ 4個が回る。星（交点）を押すとすぐその 2×2 を選ぶ。何も選んでいないときは、押した所の 2×2 を選んでそのまま回せる。

### 6.3 MVPでの閾値（暫定）
- 回しきるのは 45 度より多く回して離したとき（速く払ったときは、22 CSS px 以上動かして 13.5 度以上）。値は `src/data/balance.ts` の `SWIPE`。
- タッチ/マウスの両方をPointer Eventsで実装。
- 実機で誤操作率を計測し、閾値と操作領域を調整する。
- 回転中は再入力をロックし二重発火を防ぐ。

## 7. 基本消去・連鎖

### 7.1 通常マッチ
- **同色3個以上が縦または横に連続すると消去対象**。
- 同時に成立した縦横ラインは、交差箇所を重複計上しない。
- 対角線上の3個は通常マッチ対象外。
- 3個以上を消すと、選択キャラに応じた通常効果が発動する。
- 直線の長さやL字・十字・四角そのものによる追加倍率は **なし**。
- 一度に消したオーブ数や連鎖段数による基礎ダメージ増加は可（形ボーナスではない）。

### 7.2 落下と補充
1. 成立した全マッチを同時確定。
2. 消去対象を一括削除。
3. 各列で下側に既存オーブを詰める。
4. 空きに上から新しいオーブを補充する。
5. 3個以上のマッチが成立したら連鎖を繰り返す。
6. 連鎖上限はMVPで8段（無限ループ回避の暫定値）。

### 7.3 乱数
- 乱数生成器のseedをゲーム状態に含める。
- 同じ初期盤面、seed、操作列なら同じ結果になること。
- ステージ開始時に偶発的な初期マッチを許すか、リロールで除去するかは要調整。

### 8.2 ダメージ・回復（仮計算）
- `通常量 = Σ(色ごとの基礎係数 × 消去個数 × 連鎖倍率)`
- 仮の連鎖倍率：`1 + 0.25 × (連鎖段数 - 1)`。
- プレイヤーのレベル、攻撃力、敵防御、特性倍率はゲームエンジンの別レイヤーで計算。
- 形の一致による通常攻撃倍率アップはない。
- 数値はゲームバランス検証前の仮値。表示・定義とも設定データで差し替え可能にする。

## 9. キャラ固有の「形」による必殺技

### 9.1 設計意図
通常技と異なり、**特定の色のオーブが、指定した形に並んだ場合に固有必殺技を発動**する。形は位置依存でなく盤面中の任意位置に配置可能。これは「形ボーナス」ではなく必殺技の発動条件である。

### 9.2 MVPの発動条件
| キャラ | 対象色 | 形 | 必殺技 |
|---|---|---|---|

### 9.3 判定の約束
- 必殺判定タイミングは **「攻撃」を押したとき（回し終えた盤面）、通常マッチを消す前**。
- 発動は**編成した仲間それぞれ**（2026-11-03 改定。12.7）。
- L字は上下左右の90度回転4方向に対応。十字は1種類。正方形は1種類。
- 必殺条件に使ったオーブは、同じターンの通常消去判定と重複して構わない（MVPルール）。
- 必殺は盤面中に条件が存在する場合に自動発動する。
- 固有必殺技は仲間1人につき1ターン最大1回とする（同じターンに何人出てもよい）。
- 特定形が初期状態から成立している場合でも、回し終えた盤面に残っていれば発動する（MVP）。
- **【2026-11-01 変更】必殺が出たら、その形のオーブを最初の消去で通常マッチと一緒に消す**。必殺だけで消えたオーブは通常効果を出さず、連鎖の段数にも数えない（詳細と理由は `docs/decisions.md`）。
- **将来の改善候補**：回転で新たに形を作ったときだけ発動する／条件成立後の任意タイミングで手動発動する／発動にゲージ消費を要求する。MVPでは採用しない。

### 9.4 複数条件と優先順位
- 必殺と通常マッチが同時成立した場合は、必殺判定→通常消去→連鎖→総合ダメージ処理の順。
- 必殺に必要な形だけ成立し、縦横3個消しが不成立でも、必殺技は発動する（特にヒーラーの2×2）。
- 盤面内の他の形は追加倍率に使わない。

## 10. ターン・戦闘処理順

（**2026-11-03 改定（実装済み）**：キャラ選択をなくし、仲間全員が同時に行動する。12.7）

`交点選択 → 指で回す → 2×2回転（1〜3回くり返す。この間は何も消えない）→「攻撃」→ 固有形判定 → 通常マッチ／連鎖 → 攻撃・回復反映 → 敵行動 → ターン更新 → 次ターン入力待ち`

- **【2026-11-02 決定】1ターンに3回まで回し、「攻撃」で確定する**（以前は1回転＝1ターン）。回している間に縦横3個並んでも消えない。必殺と消去は「攻撃」を押したときの盤面で判定する。
- 「攻撃」は1回以上回したときだけ押せる。
- 回数の上限は設定データ（`MAX_ROTATIONS_PER_TURN`）。
- 敵HPが0になったら敵行動なし。
- 味方HPが0になったら敗北。0未満にはしない。
- 同ターンに回復と敵ダメージが発生する場合は、味方回復→敵の攻撃の順。
- ターン処理が終わるまで操作受付を一時停止する。

### 11.15 演出の基本
- 通常マッチ：短い消去アニメと、連鎖のあとのキャラごとの攻撃演出（11.15.1）。連鎖が進むほど効果音を高くする。
- 必殺：形のオーブを金の星座線で結んで光らせ、立ち絵のカットインで技名を出し、大きなダメージ／回復の数値を出す（11.15.1）。
- **回す動き（2026-11-04 改）**：指で回している間は、4個が2×2の中心のまわりを指の角度どおりに回る（6.1）。指を離したら、離したときの指の速さで残りを回しきる（回し始めで離したら約0.5秒、残りが少ないほど短い）。回している途中に「攻撃」を押したら、回しきってから攻撃する。回せないとき（回数を使い切った・攻撃の演出中）は回さず、途中まで動いたものは元に戻す。演出×2では半分（値は `src/data/balance.ts` の `DEFAULT_ROTATE_TUNING`）。回している途中に次の操作が来たら、今の動きをすぐ終わらせて次を回す。**パズルの動き（回す・消える・落ちる）は、端末の「視差効果を減らす（動きを減らす）」設定でも、ふつうと同じに見せる**（2026-11-03 ユーザーの決定。どう動いたかが分かることはパズルに欠かせず、だれでも同じ感覚で遊べるように）。
- **補充の動き（2026-11-03）**：消えたマスの上のオーブは元の位置から下へすべり落ち、新しいオーブは盤面の上（枠の外から見えない所）から落ちてくる。列ごとに少しずつずらし、着地で小さくはずむ。0.38秒ほど（落ちる距離で少し長く。演出×2では半分）。
- **演出の強さは「ふつう」で様子を見る（2026-11-03 決定）**。派手にするほど見栄えは上がるがテンポが落ちるので、バトル画面を作り込むときに実機で確かめて調整する。
- タッチ面積・セーフエリア・読みやすさ・色覚の違い・軽いエフェクトに気を配る。端末の「視差効果を減らす（動きを減らす）」設定では、繰り返す動きを止める。
- オーブやスキルの説明は、キャラや仕組みが増える段階でチュートリアルを段階的に開放する。

- **バトル突入の画面（2026-11-04）**：バトルに入るときは「バトル開始」の帯（ステージ番号・敵の名前）を出し、そのあいだにオーブ・背景・カットインの絵を読み込む。読み込み済みなら約0.65秒、まだなら最大1.5秒まで待ってから消える（`src/data/heroFx.ts` の `BATTLE_INTRO`）。オーブと背景の絵は、アプリを開いたときから読み込み始めておく。オーブの絵が遅れて出るのを隠すため（ユーザーの指摘）。

### 11.17 ストーリーの会話（2026-11-04 実装）

### 11.15.1 攻撃・回復・必殺の演出（2026-11-04 決定・実装）

- **必殺技**：盤面の形を星座の線で結ぶ（0.7秒）→ **立ち絵のカットイン**（その仲間の色の帯に立ち絵が入ってきて、名前と技の名前を出す。0.9秒）→ **その仲間だけの技**が敵（回復役は味方の HP の欄）に当たり、大きな数値を出す（約0.8〜1.1秒）。必殺は消去の前に出る（9.3）。

### 12.7 戦い方の改定（2026-11-03 決定・実装済み）
キャラは12人から増やさない（2026-11-03 決定）。そのため、12人それぞれに長く愛着を持って育てられること（育てる喜び）と、キャラ同士の差別化をいちばん大事にする。そのうえで戦い方を次のように改めた（2026-11-03 にユーザーの決定で、試作で切り替えずに最初から置き換えた）。

- **出撃した仲間（1〜4人）が同時に行動する**。毎ターン「行動するキャラを選ぶ」操作はなくす（バトル画面のキャラのカードは、だれが動いたかを光らせる表示にする）。
- **各キャラは、自分の色（必殺の色）のオーブが消えたときだけ行動する**。攻撃キャラは自分の色で攻撃、回復役はピンクで回復。ほかの色が消えても行動しない（連鎖のきっかけにはなる）。
  - 例：赤3人なら、赤を消すと3人分の攻撃。赤2人＋回復1人なら、赤とピンクを同じターンに消せば攻撃と回復が両方起きる。
  - 同じ色3人は当たれば大きいが、その色を消せないターンは何もできない。色がばらばらの編成は毎ターン何か起き、安定する。
- 色ごとのキャラは3人ずつ（赤：おひつじ・おうし・しし、青：ふたご・さそり・いて、緑：てんびん・やぎ・うお、ピンク：かに・おとめ・みずがめ）。
- 必殺技は仲間それぞれの形が毎ターン有効（同じターンに何人出てもよい。それぞれ1ターン1回）。
- 係数：攻撃キャラは自分の色だけ 12、回復役はピンクだけ 9（標準。2026-11-04 から防御とのつり合いで 11〜13・8〜10。12.11）（`src/data/heroes.ts` の `ATTACK_COEF`・`HEAL_COEF`）。自動の試行（`npm run bench`）で、最初の編成（おひつじ・いて・おとめ）の 1-1〜1-5 は改定前とだいたい同じ速さで倒せる（1-5 は勝率が少し上がった）。回復役のいない赤3人の編成は 1-5 でほとんど勝てない（赤を消せないターンは何もできず、回復もできないため）。
- バトル画面の仲間のカードは、押すとその仲間の必殺の形（盤面の下に全員分並べてある）を光らせる。その段で動いた仲間のカードを光らせる。

  - かに座 盾：回復（必殺も）したターンは、敵の攻撃を3割減らす。
  - おとめ座 大回復：ピンクを一度に4個以上消すと、その段の回復が ×1.5。案の「悪い状態も治す」は、悪い状態が無いので入れていない。
  - みずがめ座 恵みの雨：回復（必殺も）したら、その量の3割を次の2ターン、毎ターン回復する。
  - **処理の順**：必殺 → 消去と連鎖 → 回復 → 敵へのダメージ → 恵みの雨（前のターンから続く分）→ 毒 → 敵の攻撃（盾はここで効く）。毒で敵を倒せば、敵は攻撃しない。
  - 毒も恵みの雨も、新しくかけた方が強いときだけ上書きする（同じ強さなら残りターンは戻らない）。
  - 盾と恵みの雨は、かに座・みずがめ座が回復の行動をしたら付く（HPが満タンで実際には増えなくても）。均衡は「同じ段」に消えた色で数える（案は「同じターン」。連鎖の段ごとに攻撃するため）。
  - 自動の試行の数値は、自動プレイヤーが遠距離・均衡・溜め・毒・盾・雨を見込まずに打ったときの値（実際の遊びでは、特性を生かすともっと速くなる）。
  - 毒・恵みの雨・溜めはターンをまたぐので、途中のバトルの状態（`BattleState.traits`）に持つ。前の版の保存には無くてよい。
  - 自動の試行（skilled 150戦、1-5）：最初の3人 勝率95%・11.7ターン（改定前 91%）、ふたご・さそり・かに 75%・17.1ターン、てんびん・やぎ・うお・みずがめ 100%・21.3ターン（緑は1-5の耐性）。

### 12.10 76星座の加護（スキル。2026-11-03 方向性を決定、中身は未決定）
- 残りの76星座は「加護」として、キャラに付け替えて使う（12.2）。キャラは増えなくても、組み合わせで遊び方を広げる。
- **ユーザーの案**：加護を付けると、オーブを消した数に応じてゲージが溜まり、満タンになるとスキルを使える。**スキルごとにゲージの満タンの量が違う**（強いスキルほど多い）。
- **特性との分け方**：特性（12.8）は「キャラ固有・いつも効く・自分の色の攻撃や回復の伸び方」。加護のスキルは「付け替えられる・使うときを自分で選ぶ・盤面、ターン、守り、一時的な強化に効く」。加護で「連鎖で伸びる」「量で伸びる」など特性と同じ伸び方は作らない。

### 12.11 防御力と敵の色の弱点（2026-11-04 決定・実装。数値は仮）
- **防御力**：キャラごとに持つ（レベルで伸びる）。出撃した仲間の合計で、敵の攻撃で受けるダメージを**割合で**減らす：受けるダメージ = 敵の攻撃 × 1000 ÷（1000 ＋ 防御の合計）、四捨五入して最低1（`src/data/balance.ts` の `DEFENSE`・`damageTaken`。2026-11-07 に数値を10倍にしたので 100 → 1000）。防御500なら約3割減る。編成の画面に、防御の合計と減る割合を出す。
- **防御と攻撃のつり合い（ユーザーの決定）**：防御の高い壁役は攻撃（回復）を少し下げ、低いキャラは少し上げる。2026-11-07 からはタイプ（12.13）で決める。下の表は2026-11-04〜11-07 の値（10倍前）。

|---|---|---|---|---|---|---|
| おひつじ座 | 12 | 12 | | てんびん座 | 14 | 12 |
| おうし座 | 24 | 11 | | さそり座 | 6 | 13 |
| ふたご座 | 10 | 12 | | いて座 | 10 | 12 |

- **敵の色の弱点・耐性**：敵ごとに弱点の色と耐性の色を1つずつ持つ。その色の仲間の攻撃は、弱点なら ×1.5、耐性なら ×0.7（`WEAKNESS`）。**必殺にもかかる**（ユーザーの決定）。回復にはかからない。バトルの敵の欄・クエスト選択・図鑑に、オーブの絵つきで「弱点」「耐性」を出し、弱点・耐性で当たった数値には小さく「弱点」「耐性」と添える。
- **敵の攻撃の見せ方**：クエスト選択と図鑑の「攻撃」「強攻撃」は敵のステータス（防御をかける前の値）。バトルの強攻撃の予告は、実際に受ける量（防御で減らした量、例「−690」）を出す。
- **丸め**：通常の攻撃は「係数×個数×倍率（連鎖・特性・弱点）×レベル」を全部かけてから1回だけ四捨五入する。必殺のダメージも「威力×レベル×弱点」をかけてから1回だけ。.5 は切り上げ（小数の誤差で切り捨てにならないようにする）。

- **敵の強さの調整（2026-11-04）**：防御と弱点で楽になった分、敵の攻撃を約1.3倍に、赤が弱点の敵（1-1・1-3・1-5）の HP を上げた。自動の試行（`npm run bench`、上手な自動プレイヤー300戦。自動プレイヤーも防御と弱点を入れて見積もる）で、最初の3人の平均ターンは 1-1 5.3／1-2 7.5／1-3 9.5／1-4 11.4（勝率99.7%）／1-5 12.3（勝率91%）。改定前（1-5 勝率90%・12.9ターン）とほぼ同じ。

### 12.12 お邪魔の星屑（敵のギミック。2026-11-07 ユーザーの決定・実装。数値は仮）
- 第2章の敵は、何ターンかごとに盤面のオーブを**黒い「星屑」**（`'junk'`）に変える。ユーザーが4つの案（お邪魔の星屑・封じの鎖・色の盾・大技の予告）から選んだ。
- **星屑のふるまい**：
  - 星屑どうしは3個並んでもそろわない。回すことはできる（ふつうのオーブと同じく2×2で動く）。
  - 消去の段で、**消えるマス（通常マッチと必殺の形）の上下左右にある星屑は一緒に消える**（ななめは消えない）。一緒に消えた星屑は、通常効果にも連鎖の段数にも数えない。
  - 消えたあとは、ほかのオーブと同じく下に詰めて落ちる。上からの補充では星屑は出ない。
  - 必殺の形の判定では、星屑はどの色にも当たらない。
- **敵の行動**：敵ごとに `junk: { every, count, max }`（`src/data/enemies.ts`）。敵の攻撃のあとで残りターンを1減らし、0 になったら星屑でないマスから乱数（seed）で count 個を選んで星屑に変え、every に戻す。盤面の星屑は max 個まで。敵を倒したターンと、仲間が倒れたターンはまぜない。
- **予告**：バトルの敵の欄に「星屑まで あと○ターン」、まぜるターンは「ターンの終わりに星屑を○個（盤面に○個まで）」（2026-11-07 に1行に収まるよう短くした）（上限に近いと実際に増える数は少なくなるため、上限も添える）。クエスト選択と図鑑にも「○ターンごとに○個（最大○個）」を出す。「攻撃」で一緒に消える星屑にも、消えるオーブと同じ白い輪をつける。
- **見た目**：くすんだ黒紫の玉に、灰色の四つ角の星（`public/art/orbs/junk.webp`。2026-11-07 にユーザーが作った絵に差し替え。光らせない）。遊び方の「バトルの基本」に1ページ足した。
- 第2章の割り当て（every／count／max）：2-1 3／1／3、2-2 2／2／4、2-3 2／2／5、2-4 3／3／6、2-5 2／2／6。2-3〜2-5 は強攻撃も持つ。

### 12.14 ぶつかり岩（敵のギミック。2026-11-12 ユーザーの決定・実装。数値は仮）
- 第3章の敵は、何ターンかごとに盤面のオーブを**岩で固める**。神話でアルゴ船が抜けた「ぶつかり合う岩（シュンプレガデス）」から。ユーザーが3つの案（ぶつかり岩・渦潮・しかけなし）から選んだ。
- **岩のふるまい**：
  - 岩で固まったオーブを含む 2×2 は**回せない**（その 2×2 を選ぶと枠が灰色になり、回そうとすると枠が揺れる）。
  - 固まったオーブの色はそのままで、**そろえば消える**。必殺の形にも数える。
  - 消去の段で、**岩のマスか、その上下左右のマスが消えると岩は割れる**（ななめは割れない）。割れた岩のオーブは、自分が消えるのでなければ残り、また回せるようになる。
  - 割れなかった岩は、その下でオーブが消えれば、オーブと一緒に落ちる。
  - 星屑（12.12）と岩は重ならない（星屑を岩で固めない・岩のオーブを星屑にしない）。
- **敵の行動**：敵ごとに `rock: { every, count, max }`（`src/data/enemies.ts`）。敵の攻撃のあと（星屑をまぜたあと）に残りターンを1減らし、0 になったら、星屑でも岩でもないオーブから乱数（seed）で count 個を選んで固め、every に戻す。盤面の岩は max 個まで。**回せる 2×2 が `ROCK.minFreeIntersections`（6。16のうち）より少なくなるマスは選ばない**（`src/data/balance.ts`）。岩が落ちたせいで回せる 2×2 が `ROCK.minFreeAfterDrop`（4）より少なくなったら、落ちた岩を下の行（同じ行なら右）から順に割る（手詰まりを防ぐ）。敵を倒したターンと、仲間が倒れたターンは固めない。
- **状態**：`rocks`（岩のマスの一覧）と `enemyRockIn`（固めるまでの残りターン）。固める敵だけが持つ。
- **予告**：敵の欄の1行に「岩まで あと○ターン」、固めるターンは「ターンの終わりに岩で○個固める（○個まで）」。星屑もある敵は「星屑 あと○・岩 あと○」と短くまとめる（盤面を小さくしないため）。クエスト選択と図鑑にも「○ターンごとに○個固める（最大○個）」を出す。
- **見た目**：オーブの色と記号が透けて見える、ひびの入った灰色の石の輪（CSS・SVG。絵の部品ができたら差し替えてよい）。固まったオーブは少しくすませる。遊び方の「バトルの基本」に1ページ足した。
- 第3章の割り当て（every／count／max）：3-1 3／1／2、3-2 3／1／2（星屑 3／1／3）、3-3 2／2／4、3-4 3／1／3（星屑 2／2／5）、3-5 2／2／4（星屑 3／2／4）。3-2・3-4・3-5 は強攻撃も持つ。弱点・耐性：3-1 赤・青、3-2 緑・赤、3-3 青・緑、3-4 赤・青、3-5 青・赤。
- 自動の試行（skilled 60戦、最初の3人 Lv8・てんびん座 Lv1〜6、3-4 からはいて座の代わりにふたご座 Lv1〜3）：3-1 勝率100%・10.9ターン、3-2 12.1、3-3 13.5、3-4 14.2、3-5 16.6。自動プレイヤーは岩を割ることを狙わないので、人はもう少し楽になるはず。

## 13. ゲーム状態の型（案）

```ts
type OrbColor = 'red' | 'blue' | 'green' | 'pink';
type HeroId = 'aries' | 'taurus' | 'gemini' | 'cancer' | 'leo' | 'virgo'
  | 'libra' | 'scorpio' | 'sagittarius' | 'capricorn' | 'aquarius' | 'pisces';
type Direction = 'clockwise' | 'counterclockwise';
type Cell = OrbColor | 'junk'; // 'junk' はお邪魔の星屑（12.12）
type Board = Cell[][]; // 5x5

interface PartyMember { id: HeroId; level: number } // M4

interface BattleState {
  board: Board;
  party: PartyMember[];   // 始めたときの仲間（1〜4人）とレベル（M4）
  turn: number;
  partyHp: number;
  partyMaxHp: number;
  enemyId: string;
  enemyHp: number;
  enemyMaxHp: number;
  enemyChargeIn: number | null; // 強攻撃までの残りターン
  rngSeed: number;
  status: 'playing' | 'victory' | 'defeat';
  stats: BattleStats;     // リザルト用の記録
}

// 1ターンの操作：1〜3回の回転（「攻撃」で確定）。仲間全員が同時に行動するので、キャラは選ばない
interface TurnAction { rotations: { row: number; col: number; direction: Direction }[] }
```

エンジン関数案：
- `rotate2x2(board, row, col, direction): Board`
- `findMatches(board): MatchGroup[]`
- `detectHeroSpecial(board, heroId): SpecialResult | null`
- `collapseAndRefill(board, rng): {board, rng}`
- `resolveTurn(state, action): TurnResult`
- `formatTurnEvents(result): BattleEvent[]`

### パズル
- [ ] 2×2回転で4個以外の位置は不変。
- [ ] 3個以上の縦横ラインのみ通常消去。
- [ ] 消去→落下→補充→再判定の連鎖が正しく処理される。
- [ ] 同seed＋同操作列で同じ結果。
- [ ] **形ボーナス倍率は存在しない**。

### キャラ・必殺
- [ ] 出撃した仲間（1〜4人）全員が同時に行動し、各キャラは自分の色のオーブが消えたときだけ攻撃・回復する。
- [ ] おひつじ座の赤L字が回転4方向で判定される。
- [ ] いて座の青十字が判定される。
- [ ] 1ターンに3回まで回せ、回している間は何も消えず、「攻撃」で確定する。
- [ ] おとめ座のピンク2×2が判定される。
- [ ] 必殺条件を満たしても、未選択キャラの技は発動しない。
- [ ] 2×2のピンクが消去不能でも、おとめ座の必殺回復は成立する。
- [ ] 共有HPが1本だけ表示され、回復と被弾が正しく反映される。

## 18. アート素材（画像部品）

### 18.1 作り方の流れ
1. この仕様書（11章・18章）をもとに、画面全体のイメージを作り直す。
2. 気に入った案から、**部品ごとに**高画質で書き出す（18.3 の一覧）。
3. 部品をアプリに組み込み、実機（iPhone）で見え方を確かめる。

手順1に使うプロンプトは `docs/art-prompts.md`（雰囲気の方向 A〜D × 画面）。

画面全体のイメージは「見た目の目標」として使い、アプリにはそのまま貼らない。アプリは部品を組み合わせて画面を作る。

### 18.2 部品画像の共通ルール
- **文字を入れない**。ボタン名・見出し・数値・説明はアプリ側で描く。生成した画像の日本語は崩れやすく、文言の修正や数値の更新もできなくなるため。例外はロゴだけ。
- 背景が透明な PNG（背景画像は除く）。
- 解像度は iPhone の3倍表示に合わせる（1pt = 3px）。画面いっぱいの背景は最大の端末（440×956pt）に合わせて **1320×2868px**。
- iPad の背景は別に **2064×2752px**（iPad Pro 13インチ 1032×1376pt の2倍表示）。iPhone 用の背景をそのまま使う場合は、中央の列（左右 1032px 分）に主な絵を寄せ、端を切っても成り立つ絵にする。キャラや盤面の部品は iPhone と同じ画像を使う（列が広がる分は2倍以上の解像度で足りる）。
- 枠・パネル・ボタンは、伸ばしても四隅の飾りが歪まないように作る（四隅に飾り、辺と中央は無地か繰り返しの模様。いわゆる9スライス）。
- 1枚に1部品。光（グロー）や影は部品に含め、まわりの余白は均等にとる。
- 同じ種類の部品は、大きさ・光の当たる向き（左上から）・線の太さ・金色の色味をそろえる。
- オーブの記号と必殺の形は、本仕様（11.13・9.2）のとおりに描く。

## 19. 課金・ガチャ・オンライン機能（将来）

2026-11-02 決定：ガチャ・課金・通貨・スタミナはすべて入れる。フレンド・ギルドなどのオンライン機能もいずれ入れる。中身と時期は未決定（16章）。ここには、入れるときに守ることと、先に決めておく必要があることをまとめる。

### 19.1 サーバーが必要になる理由
- 有償の通貨・ガチャ・スタミナを端末の中だけで管理すると、改ざんで増やせてしまう。残高・ガチャの抽選・購入の記録はサーバーで持つ。
- 機種変更や再インストールで、購入した通貨やキャラが消えないようにする（アカウントとデータの引き継ぎ）。
- バトルそのもの（`src/game/`）は今のまま端末で動かす。報酬を受け取るときにサーバーで記録する。
- サーバーの仕組みは未決定。候補の一つは、トランプゲーム集（high-valley/Card-Online-Game）で使っている Firebase。

### 19.2 App Store で守ること
- アプリ内で売るデジタルの物（通貨・スタミナ回復・ガチャを回す権利など）は、Apple のアプリ内課金で売る（審査ガイドライン 3.1.1）。
- アプリ内課金で買った通貨は**期限切れにしない**。復元できる購入には復元の手段を用意する（3.1.1）。
- ガチャ（お金で買える、中身がランダムな物）は、**買う前に排出確率を見せる**（3.1.1）。App Store Connect でも「ルートボックスあり」と申告する。
- チャットや投稿（ギルドなど）を入れる場合は、不適切な投稿を防ぐ仕組み・通報・ブロック・問い合わせ先を用意する（審査ガイドライン 1.2）。13歳未満の利用者にはソーシャル機能を出さないことも求められうる。

### 19.3 日本の法律で確かめること（公開前に専門家に確認する）
- **資金決済法**：お金で買う通貨（有償の星晶石など）は「前払式支払手段」にあたる。未使用の残高が基準額を超えると届出などが必要になる。無償で配る通貨と分けて管理する。
- **景品表示法**：特定の組み合わせをそろえると別の景品がもらえる「コンプガチャ」は禁止。
- 業界団体のガイドライン（ガチャの確率表示や、未成年の課金上限など）にも合わせる。

### 19.4 先に決めておくこと
- 有償通貨と無償通貨を分けるか（法律上は分けて管理する必要がある）。
- ガチャで出るもの（キャラ・装備・76星座スキル）、確率、天井（一定回数で確定）を設けるか。
- スタミナの上限・回復時間・回復手段。
- 未成年の課金上限を設けるか。
- 設計原則5（育てたお気に入りのキャラを長く使える）と、ガチャで新キャラを出すことをどう両立させるか。
- **スキン（着せ替え）**（2026-11-03：将来入れる）：見た目だけで性能は変えない。手に入れ方（ガチャ・イベント・購入）と、保存の形（キャラごとに選んでいるスキン）は入れるときに決める。持っているスキンの記録はサーバーで持ち、売るならアプリ内課金（復元つき）、ガチャで出すなら確率を見せ、スキンをそろえると景品がもらえる形にはしない（19.1〜19.3）。スキンの露出も 19.5 の表で確かめ、基本の姿より上げない。

### 19.5 年齢区分の見立て（2026-11-02 時点）
App Store の年齢区分は 4+／9+／13+／16+／18+。申告した内容でいちばん厳しいものが区分になる。

| 内容 | 申告の目安 | 区分 |
|---|---|---|
| ガチャ（ルートボックス） | あり | 9+（オーストラリアは 16+） |
| 戦闘（剣・弓・魔獣、血の表現なし） | まれ〜頻繁 | 9+（まれ）〜13+（頻繁） |
| いて座の衣装（胸元の露出） | 性的でない程度の「刺激的なテーマ」がまれ | 9+ |
| 同上を「性的な内容・露出」と判断された場合 | まれ | 13+ |
| ランキングを競うイベント | 頻繁 | 13+ |
| チャット・投稿 | あり | 4+（それ自体では上がらない） |

- 参考画像とガチャを前提にすると、**全世界向けは 13+ を狙うのが現実的**。9+ に収まる可能性もあるが、衣装・戦闘・イベントの判断次第で上がるので、余裕を見て 13+ にしておくと審査で区分を直される心配が少ない。
- 9+ を狙うなら、いて座の衣装の露出を控えめにし、戦闘は「まれ」と言える表現にとどめ、ランキングのイベントを頻繁に開かない。
- オーストラリアでは、ガチャがある時点で 16+ になる。
- 区分は App Store Connect で申告し、最終的には審査で判断される。キャラの衣装を本番の絵にするときに、この表で確かめ直す。
